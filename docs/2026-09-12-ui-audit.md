**日期**：2026-09-12
**范围**：`dsh-plugin-mobile-ui` 全部客户端表面（抽屉 / 启动页 / 工具卡 / 本插件设置节 / 宿主设置弹层 / 键盘适配 / tether 反制）

## 1. 结论摘要

**没有 P0。** 插件不存在会崩溃、会白屏、会让宿主显示 "Failed to load plugins" 的路径；资源管理是规范的（`document`/`window`/`visualViewport` 监听、`setInterval`/`setTimeout`、`ResizeObserver`、`MutationObserver` 全部成对释放，逐条核对过）。

**但有两处代码级 P1 必须处理**（§3A）：

1. **默认配置下替换了 4 张官方工具卡**，而三处注释都写着「默认列表为空」——`read`/`grep`/`edit`/`write` 是官方注册的 key，被我们的卡片顶掉后，官方卡上的**「在轨迹中查看」与「打开文件（含行号）」、写入/编辑的 diff 视图**都消失了，而且没有开关能恢复（§3A.2）。**待你决策**。
2. ~~`apply()` 丢掉了 slot 系统的注销器~~ —— **首份静态审查的这条是误报，已撤回**（八处回调都是简洁箭头体，隐式返回注册器）；详见 §3A.1 与 §5。

> **批次 A 已实施**（§5b）：命中区、中英文字宽自适配、浅色对比度、渐隐可见性、`settings-chrome` 选择器泄漏、面板圆角、遮罩/面板动效配对，共 7 项，每项都有改前/改后实测值，并新增两个回归脚本。
>
> **批次 B 已实施**（§5c）：拖拽脱离 React state（每次滑动的布局次数 42 → 0）、工具卡展开/滚动/底色、`TYPE_LH` 行高尺度、＋/× 与「重放」命中区、状态点配色与无障碍、`[props]` 依赖身份、刷新按钮由连接状态派生、viewport 的失效后回调。批次 C 待办。

实测发现 **10 个真实缺陷**（7 个实测确认、3 个代码确认），其中影响手机日常使用的是这四条：

1. **「导航」是抽屉的唯一入口，命中区只有 26×25px**（实测）——远低于 44×44。
2. **英文界面下「Navigation」标签会压到宿主第一个标签**（实测：中文字宽 26px，英文 64.8px，宿主首标签在 x=76）。
3. **浅色主题下 12px 次要文字对比度 3.71:1、强调色文本 4.23:1**，低于 WCAG AA 的 4.5:1（实测令牌值 + 计算）。
4. **「列表还有更多」的渐隐提示完全不可见**（实测：渐隐层 y881–915，被 z-index:2 的不透明 footer y846–915 整块盖住）——JS 算了 `moreBelow` 却没有任何视觉产出。

另外发现一个**选择器前缀泄漏**（`settings-chrome` 的 `[class*="_nav"]` 命中了 `_navList` / `_navLabel` / `_navTitle`，实测 padding/gap 落在错误的元素上），以及**三处被实测推翻的怀疑**（见 §5）——其中「插件没声明 `box-sizing` 会导致整宽子元素溢出」这条如果不去量就会写进报告，实测是 border-box、无溢出。

四方面的优化建议见 §6，按「低风险高收益 → 需要结构改动 → 需要真机」分三批。

| 动画 | 属性 | 时长/曲线 | `prefers-reduced-motion` |

### 2.6 引擎代价（实测）

| 场景 | RecalcStyleCount | LayoutCount | TaskDuration |
|---|---|---|---|
| 抽屉关闭，空闲 3s | **0** | **0** | 13.7ms |
| 抽屉打开，空闲 3s（三次采样） | 31 / 86 / 110 | 0 / 46 / 60 | 10–52ms |
| 拖拽 30 步（40px，不关闭） | **105** | **42** | 48.6ms |

**诚实结论**：抽屉打开后的空闲开销**在三次采样间波动很大**，而且把跑马灯关掉之后开销并没有下降（86/46 反而更高）——说明这部分不是插件里的热循环，更可能是宿主会话视图在这期间有更新（会话流式输出）。**没有证据支持「插件造成持续空闲抖动」**；唯一能归因到插件的是拖拽：30 步 = 105 次样式重算 / 42 次布局，约每步 3.5 次重算，与「每个 `touchmove` 触发整棵抽屉重渲染」的代码事实一致（`DrawerOverlay.tsx:875` → `981`）。

## 3. 缺陷清单

§3.1–§3.22 是**视觉 / 交互 / 度量**类（每条给出实测或计算的来源）；§3A 是**代码级**（两个独立视角静态审查 + 我对着安装的宿主源码复核）。

### P1 — 影响手机日常使用

**3.1 「导航」命中区 26×25px，且它是抽屉的唯一入口** — `实测` · `DrawerOverlay.tsx:175-206`
顶栏唯一的打开手势是这段文字标签（`left:20 top:50`，13px/500）。它和宿主「对话」「轨迹」同样大小，但宿主那些不是唯一入口。手指命中区不足会导致「点了没反应」。
**修**：给按钮加一个覆盖用的命中层（不改变文字位置与排版）：
```css
.dsh-mobile-nav-tab { position: relative; }
.dsh-mobile-nav-tab::after { content: ''; position: absolute; inset: -9px -10px; }
```
实测当前几何：标签 right=46，宿主「对话」left=76 → 水平左右各扩 10px 仍然留着 20px 间隔，安全；垂直 50..75 → 扩到 41..84，顶栏高约 90px，安全。

**3.2 英文界面下标签与宿主首个标签重叠** — `实测`
同一个标签在英文下文案是 `Navigation`：实测当前字体（13px/500、系统栈）下用 canvas 量得 **中文 26.0px、英文 64.8px**，而 `settings-chrome` 给宿主 tablist 的左边距是**写死的 56px**（`DrawerOverlay.tsx:204`）。英文标签 right ≈ 20+64.8 = 84.8 > 宿主首个标签 left 76 → **约 9px 重叠**（若把内边距算进去更多）。
**修**：不要写死 56px。改成实测宽度反推（`ResizeObserver` 量标签宽 → 写 `--dsh-mobile-nav-reserve`），或把标签固定成一个「图标+固定宽度文字框」的盒子。写死像素在只有一种语言时看不出问题——这正是它藏到现在的原因。

**3.3 浅色主题对比度不足** — `实测`+计算
- `label-tertiary` `#81858c` 在白底 = **3.71:1**，却被用在 12px 的会话时间/路径/说明与 11px 的计数上。
- accent `#4176e6` 作为 **12px** 文本（工具卡的 `detail` 名称、队列/状态相关文本）= **4.23:1**。
**修**：12px 及以下改用 `label-secondary`（5.80:1）；`label-tertiary` 只留给 11px 分组标签这类非关键文本。accent 文本要么提到 13px/500，要么在浅色下压暗（`color-mix(in srgb, var(--accent) 85%, #0f1115)`）。深色主题两项都合格（7.3:1 / 4.66:1），**只有浅色要改**。

**3.4 「列表还有更多」的渐隐根本不可见** — `实测` · `DrawerOverlay.tsx:435-443` vs `:301-312`
实测：渐隐层 `.dsh-mobile-drawer-more` 是 `position:absolute; bottom:0; height:34px`、**z-index auto**，位于 y 881–915；而 footer 是 `position:relative; z-index:2; background:#fff`，覆盖 y 846–915。渐隐被整块压在下面 → 永远看不见，JS 里 `moreBelow` 的测量成了纯计算浪费。
**修**：把渐隐放进滚动容器内做 `position: sticky; bottom: 0`，或至少放到 footer 之上（z-index）。

**3.5 `settings-chrome` 的选择器前缀泄漏** — `实测` · `settings-chrome.ts:54-56`
`[class*="_nav"]` 想选的是导航容器，实际命中了 `_navList` / `_navLabel` / `_navTitle`。实测（宿主设置弹层）：

| 元素 | 实测 padding | 期望 |
|---|---|---|
| `_nav`（容器） | `8px 10px 0` | ✓（就是给它写的） |
| `_navList` | **`8px 10px 0`** | 应为 0 —— 现在整条标签带被下推 8px、左右各内缩 10px |
| `_navLabel` | **`8px 10px 0`** | 应为 0 —— 每个标签自己又被塞了 8/10px 内边距 |
| `_navTitle` | **`8px 10px 0`** | 应为 0（它在 `:42` 另有字号规则） |

文件头注释自己就警告过这个陷阱（`:21-25`「只匹配稳定后缀」），而 `_nav` 是四个本地名的**前缀**，不是唯一后缀。
**修**：改成结构选择器 `[role="dialog"] > nav { … }`（实测宿主结构就是 `dialog > nav`），彻底避开前缀歧义。同类隐患：`_header`（命中 `_headerTitle`）、`_title`、`_close`、`_value`/`_unit`。

**3.6 拖拽关闭时每帧 re-render 整棵抽屉** — `代码`+`实测` · `DrawerOverlay.tsx:875` / `:981`
`onPanelTouchMove` 每次 `touchmove` 都 `setDragX(...)`，而 transform 由 React 内联样式产生，且行组件没有 `memo`：一次滑动手势 = 每秒 60–120 次整棵抽屉（含全部工作区与 9 个会话行）的协调。实测 30 步 = 105 次样式重算 / 42 次布局。
**修**：拖拽期间直接写 `panelRef.current.style.transform`（rAF 内），`data-dragging` 也直接 `setAttribute`，松手时只提交一次 state。视觉效果不变，这是本审查里性价比最高的性能项。

**3.7 抽屉面板右下 30px 端帽被填平** — `实测` · `DrawerOverlay.tsx:233` / `:301-312`
实测面板 `overflow: visible`、`border-radius: 0 30px 30px 0`，而作为最后一个 flex 子项的 footer 是不透明的（`#fff`，69px 高）。`border-radius` 不裁剪子元素，于是 footer 的直角盖住了右下圆角；顶部端帽正常（header 没有背景色）。
**修**：`.dsh-mobile-drawer-panel { overflow: hidden; }`（面板内没有需要溢出的弹出层，安全）。注意面板是全高的，所以这个端帽就压在屏幕底边，视觉影响有限——这也是它一直没被发现的原因。

### P2 — 质量与一致性

**3.8 状态点语义被透明度压垮** — `计算` · `DrawerOverlay.tsx:380` / `:389` / `:598`
accent 全值 4.25:1 ✓；`done` 用 `opacity: .55` → ≈2.10:1 ✗；`connecting` 用 `.7` → ≈2.33:1 ✗，而 `disconnected` 是 `label-tertiary` 3.71:1 —— 在 `prefers-reduced-motion` 下 `connecting` 与 `disconnected` 是两个只能靠这点透明度区分的 8px 灰点。
**修**：改用语义色令牌（`--dsw-alias-state-success-tertiary`、`--dsw-alias-label-dimmed`），并且**状态不要只靠颜色**：给点加 `role="status"` + 文案（抽屉里已有「已连接」`aria-label`，把它做成可见文字更好）。

**3.9 工具卡代码块在浅色下没有底色** — `实测` · `ToolCard.tsx:186` vs `:84`
实测浅色下 `bg-base` 与 `bg-layer-1` **都是 `#fff`**，所以 `<pre>` 和卡片同色，只靠一条 0.5px 上边框分隔。
**修**：用宿主自己的代码块令牌 `--dsw-alias-markdown-code-block`（浅 `bluish-50` / 深 `bluish-900`），与宿主 Markdown 代码栅保持一致。

**3.10 工具卡展开动画与滚动细节** — `代码` · `ToolCard.tsx:165` / `:189` / `:190`
`grid-template-rows` 是布局属性，展开时每帧重排 `<pre>`（最多 2 万字符，`:351`）及其周围会话内容；`max-height: 60vh` 用的是静态视口高（键盘弹出时不会跟着缩，而 `viewport.ts` 恰恰在缩可视视口）；`overflow-y: auto` 没有 `overscroll-behavior`，滚到底会把惯性传给后面的会话。
**修**：时长 280→200ms，`.dsh-mobile-tool__body > div { contain: layout paint }`，`overscroll-behavior: contain; -webkit-overflow-scrolling: touch`，`max-height: min(60dvh, 420px)`。

**3.11 同一字号出现多种行高，缺少行高尺度** — `实测`
`caption` 12px 在四处分别是 18 / 19.8（1.65）/ 20（1.7）/ 无声明（继承 1.5）。`body` 14px 在抽屉是 1.45、在设置节是 1.5。分组标签 11px 声明 16px 而行高下限把抽屉那处抬到 16.5px。
**修**：见 §6.1 的 `TYPE_LH`。

**3.12 `--dsh-boot-*` 兜底链实际拿不到值** — `实测` · `theme.ts:56-62` / `:76-90`
`themeVar()` 的兜底是 `--dsh-boot-*`，但实测 `body` 与 `:root` 上这两个变量**都是空**（它们定义在宿主 boot 卡自己的 class 上）。正常路径下 `--dsw-alias-*` 一定在，所以不影响使用；但 `theme.ts` 注释里「即使在主题 presenter 写入之前也成立」的保证并不成立，属于「文档比现实乐观」。
**修**：要么删掉这层兜底并改注释，要么把兜底挂到我们自己的根上（`[data-dsh-mobile-ui] { --dsh-mobile-fallback-*: … }`）。

**3.13 设置节「重放」按钮既是胶囊又太矮** — `实测` · `Settings.tsx:112-124`
实测 50×30、`border-radius: 14px`（= 高度一半，视觉上是胶囊），而周围卡片是 14/16 的方角；命中区 30px 也不足。
**修**：`R.md`(12) + `min-height: 36px`。

**3.14 抽屉头部两个按钮相邻且动作相反** — `实测` · `DrawerOverlay.tsx:269-287`
`＋`（新建会话）与 `×`（关闭）都是 36×36、间距 10px、位于右上角。误触的代价是「本来想关抽屉，结果新建了一个会话」。
**修**：命中区做到 44×44（图标不变），或把「新建」移到抽屉底部/滚动列表头。

**3.15 遮罩与面板的动效不成对** — `实测`+`代码`
遮罩 200ms + `var(--ds-ease-in-out, ease)`（**fallback 是 CSS `ease`，曲线与 token 不同**），面板 220ms + 字面量 `cubic-bezier(.4,0,.2,1)`。两者相差 20ms，且在 token 缺失时会用两条不同曲线收尾。
**修**：成对统一（见 §6.4）。

**3.16 死代码与宿主漂移** — `代码` · `Settings.tsx:81-110` / `:152`、`Drawer.tsx:159-161`
`.dsh-mobile-settings__switch` / `__accent` 在 JSX 里从未渲染（「跟随系统主题」行实际是只读的），注释里「匹配 DSH 移动端开关几何」的说法对当前 DSH 构建也不成立（宿主是 36×20/padding 2/圆角 10）。若将来接线，`V.border` 轨（≈1.26:1）与 `V.bg` 旋钮对比度不足 1.4.11 的 3:1。
**修**：删掉死 CSS，或按宿主实现重写并随之加 `:focus-visible`。

**3.17 断点不统一** — `实测`+`代码`
抽屉/设置 chrome/键盘/队列反制用 `768px`，对话框反制用 `640px`（tether 自己的条件）。队列反制因此也作用在 **641–768px**——那个区间 tether 根本没注入它的规则。
**修**：把「反制 tether」的规则统一到 `640px`（跟着被反制的规则走），插件自己的手机布局保持 768px，并在代码里写清这条区分。

### P3 — 细节与整洁度

**3.18** 圆点尺寸 5/6/7/8px 表达同一类语义（启动页/会话状态/工作区/连接），建议收敛为两档（6/8）。
**3.19** `content-visibility: auto` 的占位高 56px 而实际行高 60px（`DrawerOverlay.tsx:515-516`），首次渲染滚动条会跳一下；`auto` 记住真实尺寸后不再发生。理论风险：被 `content-visibility` 跳过的那一行若正好是「当前会话」，跑马灯的 `scrollWidth` 测到的是占位值，`data-scroll` 不会置位（**失败安全**：只是不动画，不会错位）。
**3.20** 五个 sticky 标签共用 `top: 0; z-index: 1` 且都不透明，滚动时后一个直接盖住前一个——「工作区」还在屏上时就已经被「刚刚」取代。建议只让分组标签 sticky，一级标题保持静态。
**3.21** 分组标签的 `text-transform: uppercase` + `letter-spacing: .04em` 对中文完全无效（中文没有大小写），在 CJK 下只是无害的噪音；建议对 CJK 文案关掉。
**3.22** `content-visibility` 的 52/56px、`padding: 2.5px` 等魔术数字、`z-index` 2147481000/2000/3000 都只存在于注释里，没有 `Z`/`SPACE` 令牌。

## 3A. 代码级缺陷（静态审查 + 交叉复核）

这一节来自两个独立视角通读 `src/client/*` 的结果，并对着**安装的宿主源码**逐条复核过有争议的项（渲染器/连接/工具包/cordis）。标 `已复核` 的是我自己在宿主源码或本仓库代码里确认过机制的。

### P1

**3A.1（已撤回 —— 误报）** 首份静态审查报告称「`apply()` 没有返回 slot 注册的注销器，重放时会二次注册并抛错」。**这条不成立**：`index.tsx:118-193` 的八处回调都是**简洁箭头函数体**（`() => ctx.slots.register(...)`），隐式返回注册器，而渲染器契约（`SlotRegistry.register` 返回 `ctx.effect(...)`，`inject` 只清理回调交回的东西）要求的正是这个形状。已在 §5 的推翻表里记明，**未做任何改动**（给简洁箭头体加 `return` 反而是语法错误）。

**3A.2 默认替换 4 张官方工具卡，且三处注释与实现相反** `部分已复核` · `config.ts:283` vs `config.ts:280-281`、`index.tsx:178`、`ToolCard.tsx:18`
`FEATURES.toolCards = ['pwsh','read','grep','edit','write']` 非空，而三处注释都写「默认列表为空 / 直到有人主动开启」。`read`/`grep`/`edit`/`write` 正是官方组合注册的 key，因此在 `priority:-100` 下会被永久顶掉。**已复核的部分**：官方 `ToolRow`（`dsh-client-ui-tool/lib/client.js:1166`、`:1240-1248`）确实带 `inspectButton`（「在轨迹中查看」）与 `onOpenFile`（文件链接，带 `filePathLine` 行号跳转），并且 `:1207` 的 props 里还有 `diff` / `image` 分支；我们的卡片没有实现这些，也没有开关能恢复。
**修**：要么把默认值改回 `[]` 并让用户显式开启，要么补齐 `openFile` / `inspect` / diff 渲染并改掉那三处注释。**至少**不能让注释继续说谎。
（`pwsh` 这一个是惰性的：官方把它映射到 `bash` 变体，key 并不存在——所以实际被顶掉的是 4 张，不是 5 张。）

### P2

**3A.3 连接监听每个渲染都会重订阅** `已复核` · `DrawerOverlay.tsx:763-767`
`props` 不是缓存的注入面：渲染器每次渲染都构造新对象（`{ ...kit, ...injected, ...slotInjected.props, ...ownerProps }`），`standardKit` 也逐次 `{ ...standard }`。所以依赖 `[props]` 的效果会在**每次抽屉渲染**时拆掉再重加 `ctx.connection.state.subscribe` —— 会话流式运行时 `useSessions` 每次 tick 都会发生。**影响被收窄**：效果体内每次都调用 `sync()`（`:765`）且 `subscribe` 只是 `Set.add`（不立即回调），所以不会漏状态、不会留下陈旧的点；真实代价只是对一个不属于我们的服务做了无谓的监听抖动。
**修**：解构后再依赖身份：`const { subscribeConnection, getConnectionState } = props; useEffect(…, [subscribeConnection, getConnectionState])`。

**3A.4 刷新按钮的 1.2s 计时器既无清理也在说谎** `已复核` · `DrawerOverlay.tsx:1129`
`window.setTimeout(() => setReconnecting(false), 1200)` 没有句柄、没有清理；更重要的是 `data-busy` / 「已刷新」完全由这个固定计时器驱动，与真实 `connState` 无关 —— 断线时它也会在 1.2s 后显示完成。
**修**：busy 由 `connState` 派生（`reconnecting && connState !== 'connected'`），计时器存句柄并在 effect 清理里 `clearTimeout`（React 18 不再警告未挂载 setState，所以这条只是卫生问题）。

**3A.5 「设置」入口失败时静默无反应** `代码` · `DrawerOverlay.tsx:735-746` → `:1102-1107`
三级兜底（`sidebar.settings` 席位 → `settings.trigger` → 全文档按钮扫 aria-label 为 `设置`/`Settings`）都落空时返回 `false`，而调用方忽略返回值：用户点「设置」后抽屉关闭，**什么也没发生**，和坏掉无法区分。第三级还写死了两种语言的标签。
**修**：拿不到入口时保持抽屉打开并显示一行「无法打开设置」，或改用 settings 服务的状态而不是 DOM。

**3A.6 `viewport.ts` 的空转与失效后重挂** `已复核（第二视角结论，我复核了代码）`
- `:165-171`：`layoutRef` 只在**宽度变化**时重置，而 `innerHeight` 只被抬高（`:171`）。系统栏/输入法模式变化只改高度时，`layoutRef` 停留在旧的最大值 → `covered` 长期虚高 → 没键盘也会把 frame 按缩短高度钉住（`!important`），直到旋转或真实键盘事件清除。

**修**：把「高度」也纳入重置判据；把所有这些回调登记进同一个数组，并在 disposer 首行置 `disposed` 标志、在 `sync`/`engage` 里检查。

**3A.7 我们自己把宿主设置弹层的控件改小了** `已复核` · `settings-chrome.ts:47-51` / `:61-65` / `:105-109`
移动端润色层把关闭按钮压到 32×32、`_navCell` / `_selector` 的 `min-height` 压到 32px —— 这是手机上唯一的设置界面，主控件因此都低于 44px。
**修**：视觉尺寸可保留，用 `::after` 扩命中区（或 `min-height: 44px`）。

**3A.8 `Drawer.tsx` 与 `DrawerOverlay.tsx` 共用 `STYLE_ID = 'drawer'`** `已复核` · `Drawer.tsx:69` / `DrawerOverlay.tsx:63`

## 5. 已实测推翻的怀疑（避免重复调查）

| 静态推断 | 实测结果 |
|---|---|
| 「插件没有声明 `box-sizing`，整宽子元素（`.dsh-mobile-sess`/`_ws`/`tool__head`）在 content-box 下会溢出父容器 28–32px」 | **不成立**：实测三个元素 `box-sizing` 全是 **border-box**，`rectW` 与父内容宽一致（289/289、336/338、289/297），320–768 全宽度 `scrollWidth == 视口宽`。宿主样式表里存在我们看不到的等价 reset |
| 「200ms 常驻轮询会持续触发样式失效（5 次/秒）」 | **不成立**：抽屉关闭空闲 3s = `RecalcStyleCount 0`、`LayoutCount 0`（`removeProperty` 对不存在的属性不触发失效） |
| 「会话标题没有省略号，长标题被硬切」 | **不成立**：外层确实是 `text-overflow: clip`，但省略号在内层 `span` 上（`DrawerOverlay.tsx:552-557`），只有跑马灯那一行按设计用 `clip` + 动画。非当前行仍会出省略号 |
| 「代码块浅色下看不清是因为用了错误 token」 | 半对：token 用对了（`V.bg`），但**令牌本身就是白色**（`bg-base == bg-layer-1 == #fff`），所以要看的是「该用代码块专用令牌」（见 3.9） |
| 「`bucketFor` 会把今天的会话归到『昨天』，出现『昨天』配『1小时』的自相矛盾」 | **不成立**：`today` 的日历判断（`:700`）在 `yesterday`（`:701`）之前，00:30 的会话在 02:00 一定命中 `today`。真实的（轻微）瑕疵是**跨零点**：昨天 23:50 的会话在今天 00:10 会被判成 `justNow` 显示「刚刚」而不是「昨天」。建议 `justNow` 只在当天内生效（`if (updatedAt >= startOfToday) return age < HOUR ? 'justNow' : 'today'`），其余按日历分桶 |
| 「`typography.ts` 的 `line-height: 1.5` 会盖掉各表面自己声明的行高」 | **不成立**：`[data-dsh-mobile-ui] *` 的特异性 (0,1,0) 与单个类选择器（如 `.dsh-mobile-splash__name`）**相等**，由源码顺序决定；而 `installTypography()` 在 `index.tsx:110` 先跑、样式表先入 head，所以组件自己的行高胜出——这正是设计意图 |
| 「启动页被按住时（点击任意处关闭）可能永远无法关闭」 | **不成立**：`key` 变化时 React 18 先 flush 被删子树的清理，`requestDismiss = undefined` 先执行、新实例随后重新赋值，第一次点击有效。真实但边界极窄的问题：这个单例无人持有，任何让 `SplashHost` 卸载的路径都会留下 `requestDismiss === undefined`（同时让 `Settings.tsx:230` 的 `setSplashStatus` 变成 no-op）。修法：清理时判等再置空，并去掉 `replaySplash()` 之前的状态推送 |
| 「`ToolCard` 的自动展开 effect 依赖 `failed`，会漏掉新的失败调用」 | **未证实**：宿主对每次调用按 `callId` 做 key（`block.subCalls.map(child => <ToolCallBranch key={child.callId} …>)`），不同调用会重新挂载，`open` 从 false 开始、effect 会跑。加上 `callId` 到依赖是廉价保险，不是缺陷 |
| 「`apply()` 没返回 slot 注销器，重放时会二次注册抛错」 | **不成立**：八处回调都是简洁箭头体，隐式返回 `ctx.slots.register(...)`（`index.tsx:118-122`、`128-129`、`136-174`、`189-193`、`223-237`）。渲染器要求的正是这个形状；`return` 反而无法写在简洁体里 |

## 5e. 「刷新连接」在手机上无效 —— 实测与修复（2026-09-12）

用户报告：「手机 App 切后台之后会和电脑端失去同步连接，点刷新连接也没用」。分三层查：

**① 按钮本身有效**（实测，WS 插桩）：点击后旧 mux socket 以 **code 4000 / reason "reconnect requested"** 关闭，**2ms 后**新 socket 建立，状态 **120ms 内** `connecting → connected`。整轮只创建 2 个 socket（一换一），旧的那个确实被 `ctx.connection.reconnect()` abort 掉了（对应宿主 `ConnectionController.reconnect()`：置 `immediateRetry`、`emitState('connecting')`、abort 当前 generation）。

**② 但换掉的只是「到手机本机代理」的连接**：tether 的 CHANGELOG 写明手机界面是从**本机代理** `http://127.0.0.1:<端口>` 加载的。所以 app socket 的对端是手机自己的代理；App 切后台后断掉的是代理背后的 **P2P 隧道**。`reconnect()` 换一条到本机代理的 socket 必然瞬间成功 → 状态回到 `connected`、点变蓝、而数据到不了电脑 —— 这就是「点了没用」。

**③ 客户端检测不到这种假活**：`dsh-client-connection` 里**没有心跳**（只有 `generationReadyTimeoutMs` 15s 的首代就绪计时、分片泵定时器、online/offline 监听），tether 注入的客户端脚本也**没有任何连接恢复**（实测只有：窄屏点遮罩收抽屉、就地文件查看器、设备列表三件事）。所以「半死」永远不会自己变成 `disconnected`，我们之前那套「只在 disconnected 时重连」的自动恢复同样不会触发。

**修复**（`DrawerOverlay.tsx` + 文案）：手动刷新后加一次**链路探针**——`fetch(location.href, {cache:'no-store'})`，响应里必须含宿主注入的 `__DSH_BOOT__`（实测这份壳 HTML 43KB、3ms 返回，且只有真正到达电脑才可能有该标记）。探针失败 → 进入**第三态**：

| 表面 | 正常 | 假活 |
|---|---|---|
| 状态点 | 蓝填充（已连接） | **深色圆环 + 读屏文案「链路已断」** |
| 按钮 | 刷新连接 | **重新加载**（点击 `location.reload()`） |

另外**页面回到前台时自动跑一次探针**，不必等用户点。选择「重新加载」而不是别的，是因为主机日志显示**每次页面加载都会重建隧道**（「手机已开始加载界面」后面紧跟一条新的 `连接路径: P2P 直连(NAT 打洞成功)`）；若连重新加载也回不来，问题在更外层（err 日志里的 `authentication failed` → 需要在 tether 的「主机」页重新配对）。

**验证**：新套件 `tools/verify-refresh-honesty.mjs`（10 项，全 PASS）覆盖三条路径——健康链路（换 socket、无假死状态）、模拟假活（把探针响应换成不含宿主标记的代理占位页 → 断言第三态与「重新加载」文案）、恢复后（状态回到已连接）。

**过程中挖出的一个层叠 bug（只在矮视口暴露）**：宿主把设置弹层挂在侧栏列里，而该列被我们停靠时是 `position: fixed` —— **`position: fixed` 会创建层叠上下文**，把弹层自己的 `z-index: 1000` 关在里面。竖屏没问题是因为 **tether 会给该列 `z-index: 30`**；横屏 tether 的 ≤640 规则不生效，那一列 z-index 退回 auto，于是**应用顶栏（z-index: 1）盖住了弹层顶部** —— 实测关闭按钮位置上的 `elementFromPoint` 返回的是顶栏 tab 条，按不到。修法：停靠规则自带 `z-index: 40`，不再依赖 tether 是否生效（这条也解释了为什么竖屏一直没暴露）。

**新套件** `tools/verify-swipe-and-landscape.mjs`（14 项，全 PASS）：滑动 6 项（前进/再前进/后退/垂直不动/到头不回绕/分区数量）+ 横屏 8 项（粗指针、命中手机条件、抽屉与导航入口可用、侧栏已停靠、无横向滚动、命中层生效、关闭按钮可达）。

**构建期闸门再次生效**：这一轮我又在 CSS 注释里写了反引号，`prebundle` lint 直接指到 `DrawerOverlay.tsx:167`，`verify` 因陈旧产物守卫 exit 2 —— 没有出现"对着旧产物验证"。另外 `verify-bundle.mjs` 的 `document` 桩补上了 `addEventListener/removeEventListener`（真实 document 本就是 EventTarget），同时新模块也加了能力判断，缺监听能力时静默 no-op 而不是在激活期抛错。

## 6. 优化建议（字体 / 圆角 / 布局 / 动效）

### 6.1 字体

1. **补一个行高尺度并贯彻**（改动最小、收益最直接）：

   | 步骤 | 现在实测 | 建议 |
   |---|---|---|
   | `micro` 11px | 16 / 16.5 / 继承 | **11 / 16** |
   | `caption` 12px | 18 / 19.8 / 20 | **12 / 18** |
   | `bodySm` 13px | 18.2（1.4）/ 20 | **13 / 18** |
   | `body` 14px | 20.3（1.45）/ 21 | **14 / 21** |
   | `bodyLg` 15px | 22 | **15 / 22** |
   | `display` 19px | 28 | **19 / 28** |

   做法：在 `theme.ts` 加 `TYPE_LH`，组件里成对使用。这能消掉「同一个 12px 三种行高」和「11px 标签被 1.5 下限抬到 16.5」这类不一致。
2. **浅色对比度**：12px 及以下用 `label-secondary`；accent 文本 ≥13px/500 或浅色下压暗。这条同时修 3.3。
3. **CJK**：分组标签对中文关掉 `uppercase`/`letter-spacing`；中文正文保持 `text-wrap: pretty`（已有）。
4. **保持不动**的好决定：不覆盖 `font-family`（继承 DSH 品牌字体）、代码用 `--ds-font-family-code`、工具输出 `font-variant-ligatures: none`、六处数字面全部 `tabular-nums`、`text-size-adjust: 100%` 同时作用于根与后代。

### 6.2 圆角

1. **面板加 `overflow: hidden`** —— 修 3.7，唯一的「破了」的圆角。
2. **两个字面量入 token**：`Drawer.tsx:151` 的 `10px`（建议 `R.control`，这正是宿主控件的圆角）、`DrawerOverlay.tsx:528` 的 `3px`（建议 `R.rail`，选中轨专用）。
3. **设置节 action 从 `R.lg`(14) 改 `R.md`(12) + `min-height: 36px`** —— 修 3.13。
4. 已经正确、不要动的：卡片 14 / 设置卡 16 / 圆点 `pill`；设置弹层开关的内圆角是**精确同心**的（2.5+20+17=39.5，+2.5=42，20 ≤ 2×12.5−2×2.5）；工具卡与设置卡都用 `overflow: hidden` 裁掉了直角子元素。

### 6.3 布局

1. **修渐隐**（3.4）：放进滚动容器做 `sticky bottom` 或抬到 footer 之上。
2. **修标签预留宽度**（3.2）：由实测宽度反推，不写死 56px。
3. **命中区**（3.1 / 3.13 / 3.14）：导航标签 `::after` 扩到 ≥44；`＋`/`×` 与「重放」做到 44/36。
4. **工具卡滚动与高度**（3.10）：`overscroll-behavior: contain`、`-webkit-overflow-scrolling: touch`、`max-height: min(60dvh, 420px)`、`contain: layout paint`。
5. **启动页与可视带**：抽屉已经把高度绑在 `--dsh-mobile-vv-height` 上，启动页仍是 `inset: 0`；从设置里「重放启动页」时如果键盘还在，底部状态行会落在键盘后面。建议同样绑可视带，并补 `env(safe-area-inset-left/right)`（横屏刘海）。
6. **尺度**：新增 `SPACE`（2/4/6/8/10/12/16/20，保留 11px 作为 `row-pad` 具名值——它正是 44px 行高的来源）与 `Z`（`sheet`/`splash`/`debug`/`sticky`/`local`），把 3.22 的魔术数字收进去。
7. **一个 sticky 层只有一个标签**（3.20）。
8. **断点**（3.17）：反制 tether 的规则统一到 640px；插件自身手机布局保持 768px，并在注释里写明这个区分。

### 6.4 过渡动画

1. **遮罩与面板成对**（3.15）：同一个时长、同一条曲线；优先 `var(--ds-transition-duration, 200ms)` / `var(--ds-ease-in-out, ${MOTION.ease})`——**注意现在的 fallback 写的是 CSS `ease`，那是另一条曲线**，应改成 `MOTION.ease`。这样宿主调参时插件自动跟随。
2. **拖拽移出 React state**（3.6）：rAF 写 `style.transform`，松手时提交一次 state。视觉零变化，滑动最直接的「跟手」体感提升。
3. **工具卡展开** 280→200ms（= 宿主 base；宿主 slow 是 300）+ `contain: layout paint`，保留 `grid-template-rows` 这个免测量的惯用法，**不要**给布局属性加 `will-change`。
4. **补 reduced-motion 覆盖**：目前缺 6 条 `background`/`color` 过渡与导航标签的 `color`；跑马灯那一支在 reduce 下还要恢复省略号（当前 `data-scroll` 行在 reduce 下是 `overflow: visible; text-overflow: clip` + `animation: none`，即**硬切无省略号**，见 3.8 相关）。
5. **循环动画入 token**：`MOTION.spin`（0.9s linear，spinner 用 linear 是对的）、`MOTION.pulse`（1.2s），跑马灯 6–20s 由测量决定（保持现状），并把 CSS 关键字 `ease-in-out` 换成 `--ds-ease-in-out` 的等价表达。
6. **启动页 fade 与 `MOTION.base` 解耦**：`SPLASH_TIMING.fadeMs = 200` 现在只靠注释跟 CSS 关联，建议由 `MOTION.base` 推导。
