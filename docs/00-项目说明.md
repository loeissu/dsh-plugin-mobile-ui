## 1. 项目是什么

一个**独立的 DSH 客户端插件**，为 Android 上的 dsh-tether 提供一套更优雅的移动端界面：浮层抽屉导航、启动页、移动端设置页、工具卡片，以及针对键盘遮挡和 tether 样式缺陷的客户端治理。

它**不 fork dsh-tether、不修改 DSH 源码、不注入 hack**——全部功能走 DSH 官方 slot 系统（`ctx.slots.inject` / `register`），是官方文档明确支持的扩展点，不是对抗宿主。

### 起源

> 理解 `github.com/zexadev/dsh-tether`，然后设计一套更优雅的 Android 界面 + 启动屏。

### 硬约束（逐字，不可违反）

- 不 fork dsh-tether
- 不修改 DSH 源码
- 不升级 dsh-tether 的 `androidRuntime.dsh`
- 不替换 sidebar 插槽，不停用 ui-sidebar
- 每一步在隔离 profile 验证，确认稳定再推

## 2. 为什么是「兼容插件」这条路线

三条实测结论（全部可复现，见 `docs/01-final-plan.md` §6）：

1. **`0.1.2-rc.1`（手机本地模式）与 `0.1.5-rc.x`（PC 远程模式）的 slot 面差异极小**：51 → 61 个 slot，48 个共有且签名零变化。只使用共有 slot，同一份 `lib/client.js` 即可同时服务两端。
2. **升级 Android 运行时被上游阻塞**：`0.1.5` 的 per-session 写锁依赖 `flock`，在 Android（`process.platform === 'android'`）上硬抛异常——这是不动 `androidRuntime.dsh` 的根本原因，不是保守。
3. **未声明 slot 是静默跳过，不是崩溃**（`registry.ts:201`）：插件注册 0.1.5 独有 slot 在 0.1.2 宿主上只是不渲染。但**裸 `register` 到未声明 slot 会抛异常**，所以必须用 `inject` 包裹 `register`——这是本插件每处注册的标准写法。

## 3. 核心设计决策

| 决策 | 理由 |
|---|---|
| **默认只开加法式插槽** | 失败代价不对称：加法式（list 新 id）出错最多是不出现；替换式（single/已占用 keyed）出错会删掉用户功能且手机上无退路 |
| **版本兼容靠 slot 子集，不靠版本嗅探** | 不维护「版本号 → slot 集」映射；`inject` 天然处理未声明 slot |
| **所有颜色走 DSH 语义 token** | 不写死任何色值，浅/深/跟随系统三态自动跟随宿主。两个已知的坑写死在 `theme.ts` 注释里：`--dsw-alias-brand-primary` 不是蓝色；等宽字体是 `--ds-font-family-code` 不是从未定义的 `--dsw-font-mono` |
| **配置在源码 `config.ts`，不在 cordis.yml** | 客户端插件收不到 profile 配置通道；且把「需要重新构建」当成替换式操作的故意摩擦点 |
| **抽屉走 `shell.overlay` 浮层** | `sidebar` 是 single/单声明者，接管 = 停用 ui-sidebar，违反硬约束且实测全局崩溃（`Failed to load plugins`）。浮层方案不动 sidebar，仅窄屏 CSS 抑制原生侧栏 + 重写 grid 模板，撤销即恢复 |
| **每请求读盘** | 3080 的 `lib/client.js` 是每请求从磁盘读的，改代码**刷新页面即生效**，无需重启服务 |

## 5. 字体与排版体系

两级结构：

**第一级：字号 / 圆角 / 动效 token（`theme.ts`）**

| TYPE | 值 | 用途 | | R | 值 |
|---|---|---|---|---|---|
| `micro` | 11px | 分组标签/计数/路径 | | `xs` | 5px |
| `caption` | 12px | 时间/脚注/工具正文 | | `sm` | 9px |
| `bodySm` | 13px | 次级行/工具标题/设置控件 | | `md` | 12px |
| `body` | 14px | 主列表正文 | | `lg` | 14px |
| `bodyLg` | 15px | 抽屉/弹层标题 | | `xl` | 16px |
| `display` | 19px | 启动页品牌名 | | `panel` | 30px / `pill` 999px |

MOTION：base 200ms / sheet 220ms / expand 200ms，统一 `cubic-bezier(.4,0,.2,1)`。

**第二级：渲染质量层（`typography.ts`，2026-09-12）**

作用域 `[data-dsh-mobile-ui]` 根 + 全部后代，不触碰宿主文本：

- `text-size-adjust: 100%`——退出 Android WebView 的 font boosting（根+后代都声明，该属性继承性跨引擎不可靠）
- `line-height: 1.5` 兜底——需要更紧的步骤自己声明（同特异性靠后注入赢得级联）
- `-webkit-tap-highlight-color: transparent`——行/按钮自带 `:active`，去掉系统灰闪
- 数字表面各自本地声明 `tabular-nums`（时间/计数不抖动）；刻意不设集中清单，避免双家漂移
- 等宽字体带回退链；工具输出禁用连字
- **刻意不覆盖 font-family**：DSH 品牌字体投在 body 上，插件继承才是同脸

## 7. 构建与验证

```powershell
npm run bundle        # tsdown 双产物：Node 半边 ESM + 浏览器半边 CJS（closure 外壳）
npm run verify        # 无浏览器契约验证：loader 调用 ×1、externals ⊆ 平台表、渲染冒烟
```

关键构建约束：客户端产物**必须 CJS + closure-factory**，`external` 精确对齐 `PLATFORM_MODULES`（9 项，React 不能打进 bundle）；`dsh.bundle.patch` 与 `dsh.client` 双声明缺一不可。

浏览器级验证（需 9222 端口有 Chrome 指向实例）：

```powershell
node tools/verify-drawer-overlay.mjs "<url>?token=..." <out-dir>
node tools/probe-overlap-audit.mjs   "<url>?token=..." shots-overlap   # 重叠审计
node tools/verify-tether-compat.mjs  "<url>?token=..."                 # 必须用装 tether 的 3080
node tools/verify-title-marquee.mjs  "<url>?token=..." <out-dir>
```

**三条验证纪律**（每次真 bug 教训换来的）：

1. 必须驱动真实浏览器——`verify-bundle.mjs` 单独跑会漏掉 DOM/布局真相
2. 必须在装了 tether 的环境测——隔离 profile 3099 已两次藏住真 bug
3. 断言通过 ≠ 正确——判据写错时"绿"了但什么都没测（历史案例见 STATUS §4.9）
