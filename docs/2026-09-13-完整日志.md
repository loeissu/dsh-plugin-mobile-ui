## 阶段 6 · 真机三连修（2026-09-13）

**背景**：三张实机截图分别在 12:45、15:19、16:22 报告了三个问题，前两个是**我上一轮的修复引入/未覆盖**的。

### 6.1 重载把 App 弄砖（`cbb4da4`）

- **现象**：截图显示 Chrome 错误页 `位于 http://127.0.0.1:31407/ 的网页无法加载，net::ERR_SOCKET_NOT_CONNECTED`，App 卡死只能杀掉重开。
- **根因**：阶段 4 的第三态做了 `location.reload()`；而**代理不在时重载连文档都取不到**——从正确证据（"每次页面加载都会重建隧道"）推出了错误结论。
- **处理**：第三态按钮改为**重试**：只重新探测 + 重连，**绝不导航**；第三态期间每 4s（一分钟后 15s）自动重试，恢复即自动接上；回到前台也探一次。
- **验证**：`verify-refresh-honesty` 由 12 项扩到 **16 项**，新增两条正是这次的回归：**假活下点按钮文档不变**（哨兵变量）+ **恢复后自愈**（不点任何东西、同样不导航）。

### 6.2 「复制」在手机上失效（`3bf5ba0`）

- **先排除两个嫌疑**（都有实测）：真实触摸点击**确实落在**「复制」上（`landedOn: 复制`）；把本插件 8 张样式表全摘掉，点击照样触发宿主的剪贴板写入。
- **真根因**（读宿主 `dsh-web-frontend` 源码）：

  ```js
  if (navigator.clipboard?.writeText) { try { await writeText(t); return true } catch { return false } }
  // 只有 async API *不存在* 时才走 textarea + execCommand('copy') 兜底
  ```

  Android WebView 里 async 剪贴板通常**存在但被拒** → 它 `return false`，**自己的兜底永远走不到**；调用方 `if (!ok) return` 静默返回。实测复现：`writeText` 1 次、`execCommand` **0 次**。
- **处理**：`clipboard-fallback.ts` 包一层 `writeText`，**只在被拒时**走宿主本就写好的 legacy 路径（离屏 readonly textarea + `execCommand`，并恢复用户原有选区）。真 API 先试、复制哪段文本仍由宿主决定、两条都失败时 promise 依旧 reject；**仅手机**。
- **验证**：`verify-clipboard-fallback`（9 项）读**真剪贴板**（CDP 授权）：健康 1434 字符入板 / WebView 情形兜底写入**相同文本** / 桌面不兜底且剪贴板不变。测试方法上踩过一次坑：**桩必须装在 App 启动之前**，否则桩会覆盖掉包装器，测的是桩。

### 6.3 hover 提示残留（`bc4c15c`）

- **现象**：复制成功后一个深色「复制成功」气泡永久停在输入框上方。
- **根因**：触摸点击合成 `pointerenter`，但**永不产生 `pointerleave`**，宿主的 hover-intent 打开气泡后再也收不到"指针离开"。逐项实测：等 8s 仍在；blur 无效；焦点移走无效；合成 `pointerdown` 到别处无效；**在对话区真实点击有效**；**对锚点派发 `pointerout/pointerleave` 有效**。摘掉我们的样式表照样残留 → 不是我们造成的；桌面下鼠标移开即消失。
- **处理**：`tooltip-dismiss.ts` 触摸交互后 1.2s 对可见 tooltip 的锚点补发宿主已在监听的离开事件——不隐藏、不伪造状态；仅手机。
- **验证**：`verify-tooltip-dismiss`（4 项）：手机 4.6s 后无残留，且期间**确实出现过**（防空跑，取样还抓到宿主自己的「复制成功」，等于再次确认复制成功）；桌面照常出现且不干预。
- **顺带修掉一条坏断言**：`verify-conversation-chrome` 用"标题容器 ≥45% 宽度"作为判据，但那量的是**当时打开的是哪个会话**（同一份代码 226px 与 76px 都出现过）。改为**同一时刻 A/B**：量一次 → 摘掉本插件样式 → 再量 → 断言"绝不更差"；当前会话 **226px vs 94px（+132px）**，360 下 **174px vs 42px**。

把已过期的 `docs/00-项目说明.md` 重写为权威的**完整项目说明**（16 章 / 313 行），数字全部从代码重新取（17 模块 / 5083 行 / 53 文案键零缺失 / 33 套件），并修正升级手册里两处陈旧陈述（30→32 套件、连接状态补第四态）。

### B. 隐藏窗口下触摸事件不被确认（`feb8130`）

全量套件在"重启后的 Chrome"上突然大面积失败（6/32），而**页面本身完全健康**：evaluate 1ms 响应、85 个消息节点、零异常。

逐项排除后找到唯一原因：

| 观察 | 结果 |
|---|---|
| `document.hidden` | **true**（窗口不可见） |
| `Input.dispatchTouchEvent` | 每次**超时** |
| `Page.bringToFront` | 无效（标签仍是 hidden） |
| `Emulation.setFocusEmulationEnabled({enabled:true})` | **有效**：`document.hidden`→false，同一次派发 **10ms** 确认 |

于是：**触摸类失败全部是环境假象**，包括并行会话那个套件的"断言失败"（它的断言其实是对的）。给全部 4 个派发触摸的套件加了这一行（并在注释里留下实测数据），并在项目说明的验证纪律里加了两条：①窗口不可见时触摸/绘制/焦点类断言不可靠，跑全套请用可见窗口或 `--headless=new`；②套件依赖"已打开一个会话"，新 profile 首跑要先开会话，否则会得到"元素不存在"的假失败。

**最终验证**：在 `--headless=new` + 已开一个会话的环境下，**33/33 套件全部通过**，`npm run bundle` 与 `npm run verify` 均 exit 0。

## 方法论沉淀（值得沿用的做法）

1. **真机截图是最终裁判**：本阶段 4 与阶段 6 的每一个根因都由截图或用户报告揭出，静态审查只发现了其中一部分。
2. **先证伪再归因**：怀疑自己的样式表时，先**只摘自己的**（宿主也用 `data-plugin-css` 标记，全删会把宿主一起删）；怀疑点击链时，先量"点击落在了谁身上"。
3. **状态相关的量不要写成固定阈值**：改用同一时刻 A/B（"我们 vs 宿主原样"）。
4. **测真东西**：剪贴板读真剪贴板、滚动看真 `scrollTop`、命中区用 `elementFromPoint` 逐像素游走。
5. **桩要装对侧**：要测包装器是否生效，桩必须在目标启动**之前**注入。
6. **两道闸门值回票价**：反引号预检拦了 8 次静默构建失败；陈旧产物守卫杜绝"对着旧产物验证"。
7. **失败信息要带实测值与阈值**：下次一眼能判断是回归还是环境漂移。
8. **把推翻的结论写进文档**：避免同一件事被反复调查（本项目已有 9 条，见项目说明第 14 章）。
